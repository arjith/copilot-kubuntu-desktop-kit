# Adoption and sustainable support

## The offer

An unofficial Copilot CLI integration for tested Kubuntu/KDE workflows, built
on [computer-use-linux](https://github.com/agent-sh/computer-use-linux), with
explicit consent, result verification and reversible installation.
The integration is the contribution—not a new desktop automation engine.

## The first user action

Install the tagged kit, complete the [calculator example](../examples/README.md),
verify the visible result, then demonstrate removal without disturbing existing
configuration. Invite a voluntary, sanitized compatibility report.

Seek independent non-author successes and a successful repeat after restarting
Copilot before a wider launch. Wrong-window actions, permission violations or
rollback failures block promotion.

## A 60-day evidence window

**10,000 stars is a stretch goal, not a forecast or a commitment.**
Stars indicate discovery/appreciation; they are not install or payment counts.

Advance by evidence:

1. Make one task reproducible for independent users.
2. Resolve recurring onboarding failures.
3. Submit to narrowly relevant communities under their rules.
4. Demonstrate a reviewed update and successful user retests.
5. Invite optional support for actual maintenance work.

Track verified attempts/completions, rollback failures, repeat use, upgrade
retests and actual contributions. Record the denominator for reported success
rates. Voluntary reports are a selected sample, not a population-wide measure.
GitHub traffic covers 14 days; do not sum overlapping unique-user counts.

## Distribution

- **Awesome Copilot:** use the external-plugin issue review workflow with an
  immutable tag/full commit SHA; do not edit the marketplace listing directly.
- **KDE communities/lists:** submit only where KDE workflow integrations fit;
  disclose authorship and experimental scope. Respect maturity requirements.
- **Upstream:** offer focused Copilot documentation or a verified compatibility
  fix, not an advertisement in unrelated issues.
- **Hacker News:** its rules prohibit generated/AI-edited text and automated
  posting. A maintainer must write and submit their own post; do not reuse
  generated launch copy there. A Show HN also needs a runnable project.
  Do not solicit votes.

No bought stars, exchange rings, reward-for-star schemes, automated starring,
mass unsolicited messages or coordinated engagement.

## Funding

GitHub Sponsors fits public maintenance after demonstrated usefulness:
compatibility testing, reviewed updates, documentation and upstream fixes.
Do not promise response times, guaranteed fixes or private support unless an
actual sustainable offering exists.

Patreon is a later option if users want recurring tutorials/demonstrations or
community sessions that can be delivered consistently. Repository access alone
does not establish that demand. No star-to-revenue conversion or earnings
forecast is justified without actual payments and renewals.
