01 / Get started

A fixed release.
An explicit install.

You need a working Copilot CLI and KCalc. Run these steps from your logged-in KDE Wayland session.

Review the v0.1.0 source ↗

Use this versioned local-loading path. Keep the checkout: it is also your way to remove the backend.

1

Clone and check the release

Review the source first. After cloning, compare HEAD with the full commit below before running any scripts.

Shell · source checkout
git clone --branch v0.1.0 --depth 1 \
  https://github.com/arjith/copilot-kubuntu-desktop-kit.git
cd copilot-kubuntu-desktop-kit
git rev-parse HEAD

Expected commit02d3a7f653c6038e92729b709c64cdb3a4135d49

2

Read the plan. Nothing downloads yet.

Shell · plan only
python3 scripts/desktop_backend.py install

The backend is pinned to upstream v0.7.53. Review the three binary sizes and SHA-256 hashes along with the destination.

3

Apply, then check readiness

Only continue if you accept the plan. install --apply downloads and verifies the three binaries in your per-user data directory.

Shell · explicit download
python3 scripts/desktop_backend.py install --apply
python3 scripts/desktop_backend.py doctor

Doctor is not permission. Resolve reported readiness problems before continuing; capture and control still need your approval.

4

Load locally. Select the desktop agent.

The skill list should show six skills. The next command opens Copilot with this checkout loaded.

Shell · local plugin
copilot --plugin-dir "$PWD" skill list
copilot --plugin-dir "$PWD"
Inside Copilot · agent selection
/agent copilot-kubuntu-desktop-kit:desktop-operator
Prefer a persistent install?

The local-loading path above is useful for reviewing the source first. A maintainer-run catalog also installs the same pinned v0.1.0 plugin without the deprecated direct-install route:

copilot plugin marketplace add arjith/copilot-kubuntu-desktop-kit
copilot plugin install copilot-kubuntu-desktop-kit@kubuntu-desktop-kit

Restart Copilot after installing. This installs the skills and agents, not the backend; the explicit backend setup and portal approval steps still apply.

This is the project's own catalog, not a GitHub/KDE endorsement. Awesome Copilot review is still pending.

03 / Operating boundaries

Local control.
Not local inference.

Consent is a real step in the workflow, not something for the agent to click through.

Know what can leave the desktop

Screenshots and app text can enter model context. A local stdio connection does not make model inference offline or private. Screenshots are not automatically password-redacted.

Starts on selection
Selecting the desktop agent launches its local stdio MCP, kubuntu-desktop. Plugin loading alone does not download binaries or start a desktop server. An existing global backend is not replaced.
You authorize
Portal approvals, passwords and MFA remain direct user actions. A permission denial means stop—not retry with broader access.
Restricted routes
The optional shell tool and direct input-device route are disabled. No root access or global Copilot profile overwrite is required.
Scoped, not isolated
Physical input and other controllers can invalidate focus. Do not run competing controllers. Agent instructions are not an authorization system or a security sandbox.

05 / Evidence, not promises

What has
actually passed.

This is an experimental preview, not a claim of reliable unattended desktop control.

Read the acceptance scope ↗
✓

Synthetic tests & installation gates

20 synthetic tests and the canonical plugin, skill and marketplace installation gates passed. These checks cover packaging and safety behavior—not broad GUI reliability or marketplace listing.

✓

A controlled test window

User-approved capture, focus, keypress and accessibility readback passed on the initial KDE Wayland host. That is separate from the KCalc task above.

—

Coverage is still narrow

Broad hardware, display and keyboard-layout coverage is not established. Multi-monitor, fractional-scaling and interruption behavior need explicit testing. Other host configurations are not claimed supported.

A useful report is small and specific.

Include the release, Copilot and KDE/Wayland versions, task, first failing stage, and pass/fail for the visible result and rollback. Add scale or keyboard layout only if relevant.

No tokens, private code, desktop screenshots, complete configurations or raw logs. A permission denial is a valid outcome.

06 / Roll back

The exit path,
in plain sight.

From your retained checkout, plan removal before applying it. Remove the backend before unloading the plugin.

Shell · removal plan
python3 scripts/desktop_backend.py uninstall

If you accept that plan:

Shell · explicit removal
python3 scripts/desktop_backend.py uninstall --apply

Restart Copilot without --plugin-dir. Removal refuses modified binaries, symlinks and unknown files. It does not delete personal Copilot settings or another backend installation.

If you previously installed persistently

After backend removal, run copilot plugin uninstall copilot-kubuntu-desktop-kit@kubuntu-desktop-kit for the maintainer catalog install, or copilot plugin uninstall copilot-kubuntu-desktop-kit for an older direct install, then restart Copilot. Remove the optional catalog with copilot plugin marketplace remove kubuntu-desktop-kit. None of these commands are needed for the local-loading path above.
